Workflow Skills  /  how plans look now

Claude Code shows you
the thing — not a description of it.

When a workflow skill plans, proposes, or asks something, it builds a small visual artifact that previews the actual work. You glance at it and you already know — yes, do that, or wait, let's talk. No wall of text to wade through first.

Preview the real thing

Building a screen? You see the screen. A behaviour? You can play with it. A choice? The options sit side by side.

Decide in one glance

Every artifact is shaped so the answer is obvious fast — approve, or open a conversation about one part.

No fixed layout

There is no template and no catalogue. Claude Code composes whatever view makes this particular work clearest.

The examples below are range, not a menu.  Claude Code doesn't pick from a list of layouts — it looks at what you're about to build and composes the view that gets you to a decision fastest. These are just four different situations, shown four different ways.

There is no catalogue to pick from

Claude Code looks at what you're about to build and composes the view that makes it obvious — a mockup, a live prototype, a comparison, a diagram, or something none of these examples showed. The html-doc skill carries only a design system, so every artifact looks like family, and a few examples like these as inspiration. The shape is always chosen for the work in front of it.
