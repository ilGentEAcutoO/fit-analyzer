§ 01 · ARCHITECTURE

One static frontend, one Worker, one LLM call

Stateless. No DB. The Worker is the only thing that ever sees the API key.

Solid arrows = request · dashed = response. The browser never holds the key, and Gemini never sees the user's IP — only the Worker does. That's the abuse-prevention seam.

§ 02 · SPEC DEVIATIONS

Three corrections from research

Library docs verified 2026-05-26. The spec was written before these moved.

!
Why this section exists: the implementing agent will be reading the spec alongside this plan. These are the only places the plan overrides the spec — anywhere else, the spec wins.
▶02.1 Rate-limit binding TOML worker/wrangler.toml

Spec uses binding = "RATE_LIMITER" and an inline-table simple = { limit = 10, period = 60 }. Current Cloudflare docs use name and a [ratelimits.simple] sub-table. Requires Wrangler ≥ 4.36.0. No compatibility_flags needed.

worker/wrangler.tomldiff
# before — from spec §06
[[ratelimits]]
binding      = "RATE_LIMITER"
namespace_id = "1001"
simple       = { limit = 10, period = 60 }

# after — verified against current CF docs
[[ratelimits]]
name         = "RATE_LIMITER"
namespace_id = "1001"
  [ratelimits.simple]
  limit  = 10
  period = 60

Runtime call shape is unchanged: const { success } = await env.RATE_LIMITER.limit({ key: ip }).

▶02.2 pdfjs-dist worker import under Vite web/src/lib/pdf.ts

Pin pdfjs-dist@^5. Vite needs the worker URL emitted at build time — use the ?url suffix import. Set workerSrc in the same module that uses pdfjs (module load order has burned others on this).

web/src/lib/pdf.tscanonical Vite + pdfjs v5
import * as pdfjsLib from 'pdfjs-dist';
import workerUrl from 'pdfjs-dist/build/pdf.worker.min.mjs?url';
pdfjsLib.GlobalWorkerOptions.workerSrc = workerUrl;

No CDN, no `?worker` — Vite emits the file with a hash and serves it same-origin.

▶02.3 Pages deploy flag terminal

First non-interactive Pages deploy needs --project-name or Wrangler will prompt and fail in CI / a fresh shell.

terminalfirst deploy
# confirmed current
npx wrangler pages deploy ./dist --project-name=fit-analyzer

Old wrangler pages publish is a deprecated alias — works, but use the modern verb in scripts.

Things research confirmed, no change needed
  • gemini-3.1-flash-lite and gemini-3.5-flash are both stable IDs — no -preview suffix.
  • system_instruction in snake_case is the documented form on v1beta (camelCase also works; stick with the spec's snake_case for clarity).
  • x-goog-api-key header (not URL ?key=) is current best practice and matches the spec's security rule.
  • FitReport contract (spec §04) — no library reason to touch it.
§ 03 · BUILD STREAMS

Three streams · A + B parallel, C serial

"Frontend cannot start until Worker is done." — that's the trap. The FitReport contract is frozen, so the frontend can build against the typed contract from minute one with a stub. We split into parallel streams.

Stream A · Worker
  • scaffold + wrangler.toml
  • prompt.ts (system + schema)
  • index.ts handler
  • unit tests
  • curl smoke + prompt tune
Stream B · Frontend
  • scaffold (Vite/React/TS/Tailwind)
  • types.ts mirroring §04
  • lib/pdf.ts, lib/api.ts
  • 5 components
  • App state machine
Stream C · Ship
  • local integration + state QA
  • Playwright happy-path E2E
  • wrangler deploy (worker)
  • pages deploy (frontend)
  • CORS lock + AI Studio restrict
  • README + live smoke

Step detail (collapsed)

▶A.1 Scaffold Worker ~20 min

npm create cloudflare@latest worker --type=hello-world --ts --git=no, then trim to one handler. Author wrangler.toml with the corrected rate-limit syntax (§02.1), set compatibility_date to today, and declare GEMINI_API_KEY + ALLOW_ORIGIN as expected vars. Create .dev.vars with the local key and verify .gitignore lists it before any commit.

▶A.2 prompt.ts — frozen contract surface worker/src/prompt.ts

Export three things: SYSTEM_PROMPT (spec §04 verbatim, tune later), buildUserTurn(jd, resume) returning a clearly labelled prompt string, and FIT_REPORT_SCHEMA matching the spec's schema with required: populated. Schema uses type: "OBJECT" (uppercase) per current Gemini docs.

▶A.3 index.ts — the handler worker/src/index.ts

Order is fixed: CORS preflight → method check → rate-limit (CF-Connecting-IP) → JSON-body parse → length validation → Gemini fetch with header auth → defensive JSON.parse → return. Errors return a short opaque code only — never echo upstream body.

▶A.4 Unit tests worker/src/index.test.ts · vitest + miniflare

Three tests are non-negotiable: (1) empty body → 400; (2) over-15000-char body → 400; (3) when Gemini returns invalid JSON → 502 with {"error":"parse"}, not a crash. Stub fetch to control the upstream response. Optional: 4th test verifying the rate-limit branch with a stubbed env.RATE_LIMITER.

▶A.5 Curl smoke + prompt tune ~30 min

Run wrangler dev with .dev.vars. Send 3 realistic resume/JD pairs via curl — one strong match, one moderate, one weak. The verdict bands (strong ≥75 / moderate 50-74 / weak <50) should land naturally; if every output reads as "moderate", tighten the prompt's "be honest, do not inflate" line. Also fire 12 requests in 10 s from one IP → confirm 429 trips around request 11.

▶B.1 Scaffold web/ ~15 min

npm create vite@latest web -- --template react-ts, add Tailwind via npx tailwindcss init -p, wire index.css with the three Tailwind directives. Add VITE_API_BASE to .env defaulting to http://127.0.0.1:8787 for local dev.

▶B.2 types.ts mirrors §04 web/src/lib/types.ts

Mirror the FitReport contract as TS types. The four dimension keys are a readonly tuple string-literal union — this is what catches a Worker drift later. Frontend builds against this from minute one with a stub analyze().

▶B.3 lib/pdf.ts web/src/lib/pdf.ts

Use the §02.2 pattern. Export extractTextFromPdf(file: File): Promise<string>. Catch parse failures; return empty string on failure so the UI can surface "extraction returned no text — paste instead" rather than crashing.

▶B.4 lib/api.ts web/src/lib/api.ts

Single typed function analyze(resume, jd): Promise<Result> where Result = {ok:true; data:FitReport} | {ok:false; kind:'rate_limited'|'bad_input'|'upstream'|'network'}. Map 429 to rate_limited; everything else by status code. Single source for fetch errors.

▶B.5 Components web/src/components/*

Build in dependency order so each can render in isolation: ScoreGauge (conic gradient, colour from band) → DimensionBar → FindingList (strengths / gaps with severity pills / suggestions) → ResultPanel (composes the above + skeleton on loading) → InputPanel (dropzone + paste fallback + JD textarea + disabled-until-ready button).

▶B.6 App.tsx state machine web/src/App.tsx

Five UI states — model them with a discriminated union, not booleans: {kind:'idle'} | {kind:'loading'} | {kind:'done', report} | {kind:'error', message} | {kind:'rateLimited'}. Treat rateLimited as a distinct gentle state, not "error". Two-panel desktop, stacked mobile.

▶C.1 Local integration + state QA frontend-test skill

Run both wrangler dev and vite dev together. Click through all five states by hand: idle (button disabled) → loading (spinner) → done (report renders) → error (network kill via DevTools) → rateLimited (spam the button 12×). Use frontend-test skill for the run.

▶C.2 Playwright happy-path E2E web/tests/happy.spec.ts

One test: open the page, paste a stub JD, paste a stub resume (skip PDF — file upload via Playwright + pdfjs in test env is too brittle for a 1-day MVP), click Analyze with a mocked /api/analyze response, assert the gauge shows a number and all four dimension bars render. Playwright via the project's MCP if available; else @playwright/test.

▶C.3 Deploy Worker deploy skill

npx wrangler secret put GEMINI_API_KEY, paste the user-supplied key, then npx wrangler deploy. Capture the *.workers.dev URL.

▶C.4 Deploy Pages deploy skill

Set VITE_API_BASE to the Worker URL, then npm run build && npx wrangler pages deploy ./dist --project-name=fit-analyzer (§02.3). Capture the *.pages.dev URL.

▶C.5 Lock down ~10 min

Three steps in this order: (1) wrangler secret put ALLOW_ORIGIN with the exact Pages URL; (2) in Google AI Studio, add an API restriction to the key — Generative Language API only; (3) confirm via DevTools that a request from any other origin is blocked by CORS. Without §C.5 the rate limit is the only defence — that's not enough.

▶C.6 README + live smoke README.md

README must let a stranger clone, run locally, and deploy. Include the live URL, a screenshot of the report, and the spec's §06 key-handling rules. Smoke-test the live URL on desktop and mobile (DevTools device emulation is fine for a 1-day MVP).

§ 04 · SECURITY

Concrete attack vectors → mitigations

!
The repo is public. A leaked Gemini key is a draining attack. These mitigations are non-negotiable per spec §06.
Attack vectorMitigation
Key in client bundle — attacker grabs from JS source. Worker proxy; frontend never sees the key. Verified by grep -ri "AIza" web/dist returning zero hits after build.
Key in git history — committed once, forever in git log -p. .dev.vars in .gitignore before the first commit. Pre-deploy: git log -p | grep -i "AIza" returns nothing.
Key in URL — leaks via referrer, browser history, server logs. Header auth (x-goog-api-key), never ?key=.
Quota drain — attacker hammers /api/analyze. 10 req/min/IP via CF rate-limit binding. CF-Connecting-IP as the key (Cloudflare-trusted, can't be spoofed at the edge).
Cross-origin call — attacker hosts a page that calls our Worker. ALLOW_ORIGIN locked to the live Pages URL after §C.5. OPTIONS preflight is the gate.
Wrong API surface — leaked key abused on other Google APIs. API restriction in AI Studio: Generative Language API only.
Upstream error leaks — Gemini error body returned to UI. Worker returns short opaque error codes only (parse, upstream, rate_limited). Never echo upstream JSON.
Oversized prompt — DOS via 1 MB request bodies. Reject > 15 000 chars per field with 400 before the Gemini call.
§ 05 · TEST HARNESS

Pragmatic — Unit + one E2E

Decided 2026-05-26. The harness covers what actually breaks in production: input validation, JSON parse failure, and the frontend happy path. Storybook is deliberately not in scope.

LevelScopeSpecs
unit Worker handler · vitest + miniflare · empty body → 400 {"error":"bad_input"}
· over 15 000 chars → 400
· stub Gemini returning non-JSON → 502 {"error":"parse"}
· stub RATE_LIMITER.limit returning {success:false} → 429
e2e Frontend happy path · Playwright · paste resume text → paste JD → click Analyze (mock /api/analyze) →
  gauge number visible, 4 dimension bars visible, ≥ 1 strength, ≥ 1 gap rendered
manual Live smoke · on the deployed URL · real PDF + real JD → report renders on desktop and mobile
· 12 rapid clicks → 429 banner shows
· DevTools offline → error state shows
What is NOT in the harness, and why
  • Storybook component tests — costly for a 1-day MVP; the visual review is the demo itself.
  • PDF in the E2E — pdfjs in a Playwright headless context is flaky; manual smoke covers it on the live URL.
  • Prompt regression tests — LLM output drift would need a golden-output harness; for a portfolio piece, prompt-tune by eye in A.5.
§ 06 · RISKS

What might burn the day · mitigations

RiskLikelihoodMitigation
pdfjs worker silently fails under Vite high — recurring footgun Use §02.2 pattern verbatim. Test extraction on a sample PDF immediately after B.3 — before building any UI on top of it.
Gemini JSON drifts despite responseSchema med Defensive JSON.parse in A.3. Unit test A.4(3) locks the 502 path. Live smoke (manual) catches drift.
Rate-limit binding not yet on the user's CF plan med — fairly new feature If wrangler deploy errors on the binding, fall back to a Workers KV counter keyed by IP (15-line replacement). Spec §06 calls this out as acceptable.

API key accidentally committed low if §04 followed Pre-commit hook can grep for AIza prefix; for a 1-day MVP, manual git diff --cached | grep AIza before each commit.
CORS misconfigured after deploy med §C.5 is its own task with its own verification — don't fold it into the deploy step.
