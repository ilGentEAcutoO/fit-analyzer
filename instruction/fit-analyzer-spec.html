Resume × JD
Fit Analyzer

An AI tool that scores how well a candidate's resume matches a job description — and tells them exactly what to fix. Paste a JD, drop a resume PDF, get a structured fit report in seconds.

§ 00

Mission

This file is the single source of truth. Read it fully before writing any code. It is both a human-readable plan and a work order.

For the implementing agent

How to use this spec

  1. Read every section before generating code. Do not start from section 05 in isolation.
  2. Build in the order of §08 Build Phases. Finish and verify a phase before the next.
  3. The JSON contract in §04 is frozen. Frontend and Worker must both honour it exactly.
  4. Read §06 before touching any key or network call. The Gemini API key must never leak.
  5. Respect the §09 Scope Lines — do not build anything in the "out" column.
  6. A phase is done only when its checklist and §10 Done Criteria pass.

Why this exists

This is a portfolio piece built for a Senior Software Engineer application at a product company whose flagship is a recruitment platform. The tool must prove three things at a glance to a technical interviewer:

  • React competence — the frontend is intentionally React, not Vue. This closes the one stack gap on the JD.
  • AI integration done right — a real LLM call with a schema-locked output and a rate-limited, secured proxy — not a toy wrapper.
  • Full-stack delivery — frontend, serverless API, and a live deployment, shipped end to end in a day.

Domain note: resume–JD matching is deliberately recruitment-flavoured so an interviewer instantly understands the value. The engine itself is domain-neutral — it is a "score a document against a rubric" pattern. The JD is the rubric; the resume is the submission.

§ 01

Architecture

One static frontend, one serverless endpoint, one LLM call. Stateless — no database in the MVP.

Solid arrows = request. Dashed = response. The browser never sees the API key — every LLM call is proxied through the Worker, behind a rate limiter.

§ 04

Analysis Engine

The heart of the product. Get this right first — the UI is just a renderer for what this returns.

The output contract — FitReport

The LLM must return exactly this shape. With Gemini this is enforced server-side via responseSchema (below), so there are no fences to strip. All scores are integers 0–100. Frontend and Worker both treat this as frozen.

FitReportJSON contract
{
  "overallScore": 78,
  "verdict": "strong",           // "strong" | "moderate" | "weak"
  "summary": "One or two plain-language sentences.",
  "dimensions": [
    {
      "key": "technical_skills",
      "label": "Technical Skills",
      "score": 85,
      "reason": "One concise line citing the resume."
    }
    // exactly 4 dimensions, keys below — same order every time:
    // technical_skills · experience · education · domain_fit
  ],
  "strengths": [
    { "point": "What matches well.",
      "evidence": "Paraphrased proof from the resume." }
    // 3 to 5 items
  ],
  "gaps": [
    { "point": "What is missing or weak vs the JD.",
      "severity": "high" }   // "high" | "medium" | "low"
    // 3 to 5 items
  ],
  "suggestions": [
    { "action": "A concrete edit to make to the resume.",
      "rationale": "Why it raises the fit." }
    // 2 to 3 items
  ]
}

The system instruction

Store this in worker/src/prompt.ts as an exported string. The Worker sends it as Gemini's system_instruction. Tune wording during Phase 1.

prompt.tssystem instruction — copy verbatim, then tune
You are an expert technical recruiter and resume analyst. You compare a
candidate's RESUME against a JOB DESCRIPTION and produce an honest,
evidence-based fit assessment.

Rules:
- Judge only on what the resume actually shows. Do not invent experience.
- Be honest. Do not inflate scores to be kind. A weak match must read as weak.
- Every dimension reason and every strength must point to real resume content.
- Gaps are things the JD asks for that the resume does not clearly show.
- Suggestions must be concrete, actionable resume edits — not generic advice.
- Input may be Thai or English or mixed. Analyse it natively in either.

Scoring:
- All scores are integers from 0 to 100.
- overallScore reflects the whole picture, not a strict average of dimensions.
- verdict: "strong" >= 75, "moderate" 50-74, "weak" below 50.
- The 4 dimension keys, in this fixed order:
  technical_skills, experience, education, domain_fit.

Reliability — native structured output

Gemini supports responseMimeType: "application/json" plus a responseSchema. The model is constrained to the exact shape at generation time — no prefill, no fence-stripping. Keep a defensive try/catch on JSON.parse anyway.

prompt.tsresponseSchema — condensed
{
  type: "object",
  properties: {
    overallScore: { type: "integer" },
    verdict:      { type: "string", enum: ["strong","moderate","weak"] },
    summary:      { type: "string" },
    dimensions:   { type: "array", items: { type: "object", properties: {
      key:    { type: "string" }, label: { type: "string" },
      score:  { type: "integer" }, reason: { type: "string" } } } },
    strengths:    { type: "array", items: { type: "object", properties: {
      point: { type: "string" }, evidence: { type: "string" } } } },
    gaps:         { type: "array", items: { type: "object", properties: {
      point: { type: "string" },
      severity: { type: "string", enum: ["high","medium","low"] } } } },
    suggestions:  { type: "array", items: { type: "object", properties: {
      action: { type: "string" }, rationale: { type: "string" } } } }
  },
  required: ["overallScore","verdict","summary","dimensions",
             "strengths","gaps","suggestions"]
}
§ 05

Backend — Worker

One endpoint. Rate-limit, validate, call, parse, return. Keep it boring and bulletproof.

Endpoint contract

ItemSpec
RoutePOST /api/analyze
Request body{ "resume": string, "jd": string }
Success200 · body = FitReport JSON (see §04)
Bad input400 · { "error": "..." } — empty or over 15000 chars
Rate limited429 · { "error": "rate_limited" } — too many requests from this IP
Upstream fail502 · Gemini error or unparseable output
CORSHandle OPTIONS preflight; allow only the Pages origin

Handler skeleton

worker/src/index.tsstarting point — extend, don't replace the contract
interface Env {
  GEMINI_API_KEY: string;          // secret — see §06
  ALLOW_ORIGIN:   string;          // the deployed Pages URL
  RATE_LIMITER:   RateLimit;        // CF rate-limit binding — see §06
}

export default {
  async fetch(req: Request, env: Env): Promise<Response> {
    const cors = {
      "Access-Control-Allow-Origin": env.ALLOW_ORIGIN,
      "Access-Control-Allow-Methods": "POST, OPTIONS",
      "Access-Control-Allow-Headers": "Content-Type",
    };
    if (req.method === "OPTIONS") return new Response(null, { headers: cors });
    if (req.method !== "POST")   return json({ error: "method" }, 405, cors);

    // --- rate limit by client IP (protects the free Gemini quota) ---
    const ip = req.headers.get("CF-Connecting-IP") ?? "unknown";
    const { success } = await env.RATE_LIMITER.limit({ key: ip });
    if (!success) return json({ error: "rate_limited" }, 429, cors);

    const { resume, jd } = await req.json();
    // validate: non-empty, each <= 15000 chars -> else 400

    const url = "https://generativelanguage.googleapis.com/v1beta/"
              + "models/gemini-3.1-flash-lite:generateContent";

    const res = await fetch(url, {
      method: "POST",
      headers: {
        "content-type": "application/json",
        "x-goog-api-key": env.GEMINI_API_KEY,   // HEADER — never ?key= in the URL
      },
      body: JSON.stringify({
        system_instruction: { parts: [{ text: SYSTEM_PROMPT }] },
        contents: [{ role: "user",
                     parts: [{ text: buildUserTurn(jd, resume) }] }],
        generationConfig: {
          temperature: 0.2,
          responseMimeType: "application/json",
          responseSchema: FIT_REPORT_SCHEMA,       // from prompt.ts
        },
      }),
    });
    if (!res.ok) return json({ error: "upstream" }, 502, cors);

    const data = await res.json();
    const raw = data.candidates?.[0]?.content?.parts?.[0]?.text ?? "";
    try {
      return json(JSON.parse(raw), 200, cors);   // optionally validate keys
    } catch {
      return json({ error: "parse" }, 502, cors);
    }
  },
};
  • Validation: reject empty inputs and anything over 15000 chars with a clean 400 before spending an LLM call.
  • Defensive parse: if the model ever returns non-JSON, fail with 502 — never crash, never leak raw upstream text to the UI.
  • Never echo secrets: error responses carry a short code only — never the key, never the raw Gemini error body.
§ 06

Key & Limits

The repo is public. A leaked Gemini key can be drained by anyone. These rules are not optional.

Gemini API key — non-negotiable rules
  • The key lives only as a Worker secret: wrangler secret put GEMINI_API_KEY. Never in wrangler.toml, never in source, never committed.
  • Local dev uses .dev.vars — and .dev.vars must be listed in .gitignore before the first commit.
  • The frontend never calls Gemini directly. Every model call is proxied through the Worker; the key never reaches the browser bundle.
  • Pass the key in the x-goog-api-key header — never as a ?key= URL parameter. URL params leak into logs, browser history, and referrer headers.
  • Error responses return a short code only — never the key, never the raw Gemini error body.
  • In Google AI Studio / Cloud Console, add an API restriction to the key so it only works with the Generative Language API. A restricted key that leaks is far less dangerous.
  • Before pushing: confirm no key string exists anywhere in git log -p. If one ever lands in history, rotate it immediately.

Rate limiting

Even with a secured key, an open endpoint can be hammered until the free Gemini quota is exhausted. The Worker rate-limits every request by client IP.

  • Mechanism: Cloudflare's Workers rate-limit binding — configured in wrangler.toml, no extra service. (A Workers KV counter keyed by IP is an acceptable fallback if the binding is unavailable.)
  • Budget: 10 requests per minute per IP. Tune after testing.
  • Key: the CF-Connecting-IP header — the real client IP at Cloudflare's edge.
  • Behaviour: over the limit returns 429 with { "error": "rate_limited" }; the frontend shows a friendly "try again shortly" message.
worker/wrangler.tomlrate-limit binding — confirm exact syntax in current CF docs
# the rate-limit binding needs no secret and no paid plan
[[ratelimits]]
binding      = "RATE_LIMITER"
namespace_id = "1001"
simple       = { limit = 10, period = 60 }   # 10 req / 60s per key

Components

App.tsx

Owns state: resumeText, jdText, status (idle / loading / done / error), report. Renders the two-panel layout.

InputPanel.tsx

PDF dropzone + paste fallback for the resume; textarea for the JD; the Analyze button. Disables the button unless both inputs have content.

lib/pdf.ts

Wraps pdfjs-dist. Takes a File, returns extracted text across all pages. Catches parse failures gracefully.

lib/api.ts

Single analyze(resume, jd) call to the Worker. Typed return of FitReport. Maps 429 to a distinct "rate limited" state.

ScoreGauge.tsx

The big overall score as a conic-gradient ring + verdict label. Colour shifts by band: green / amber / coral.

DimensionBar.tsx

One labelled progress bar per dimension, colour-coded by score. Rendered for all four dimensions.

FindingList.tsx

Renders strengths, gaps (with severity pills), and suggestions. The gap → fix pairing is the memorable part — make it read clearly.

ResultPanel.tsx

Composes gauge + bars + findings + the summary line. Shows skeleton on loading, a friendly message on error or rate-limit.

UX rules

  • States are explicit. idle, loading, done, error — never a blank or frozen screen. Treat 429 as its own gentle message, not a scary error.
  • Button is honest. disabled until resume + JD both have content; shows a loading label while the request is in flight.
  • PDF caveat. Thai text extraction from some PDFs is imperfect — that is why the paste fallback exists. Surface it if extraction returns suspiciously little text.
  • Responsive. two panels side by side on desktop; stacked on mobile. Web only — no native app.
  • Colour = meaning. green ≥ 75, amber 50–74, coral < 50. Same thresholds as the verdict bands.

§ 09

Scope Lines

An MVP is defined by what it refuses to do. Do not cross into the right column.

IN — build this
  • Resume via PDF upload or pasted text
  • JD via pasted text
  • One Worker endpoint, one LLM call
  • Per-IP rate limiting with a 429 response
  • Structured FitReport: score, 4 dimensions, strengths, gaps, fixes
  • Two-panel responsive web UI
  • All four loading / error states
  • Live deployment + README
OUT — do not build
  • Accounts, login, or auth of any kind
  • Saved history / dashboards / a database
  • React Native or any mobile app
  • Batch analysis of multiple resumes
  • PDF export of the report
  • UI internationalisation (input can be TH/EN — that is free)
  • Response streaming (stretch only)
§ 10

Definition of Done

The project ships only when every line below is true.

  • A resume PDF + a pasted JD produces a full, correct FitReport on screen.
  • The Worker returns valid JSON on every run; malformed model output degrades to a clean 502, never a crash.
  • Rapid repeated requests from one IP trip the rate limiter and return 429.
  • The Gemini API key exists only as a Worker secret — it appears nowhere in the frontend bundle, in wrangler.toml, or in git history.
  • The UI handles idle, loading, done, error, and rate-limited without a blank or frozen state.
  • The app is deployed and reachable at a public URL, working on both desktop and mobile.
  • README.md lets a stranger clone, run locally, and deploy it.
  • Nothing from the §09 "out" column was built.

Talking Points

What to say about this when it comes up in the interview.

React, proven

"The frontend is React + Vite + TypeScript — here is the live build, not a slide." Closes the stack-gap question before it is asked.

AI done properly

A real LLM call using Gemini's native structured-output schema — the model is constrained to the exact JSON shape server-side. Talk through the prompt design and the defensive parse.

Full-stack & shipped

Frontend, serverless API, and a public deployment — delivered end to end on Cloudflare in a day. Show the URL.

Security & abuse instinct

The key is a Worker secret, proxied, passed via header not URL; the endpoint is rate-limited per IP to protect the quota. Mention it unprompted — it signals seniority.
